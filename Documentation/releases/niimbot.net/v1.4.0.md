`Niimbot.Net` is the standalone C# protocol + transport library for NIIMBOT thermal printers (GPL-3.0), independent of any UI or label engine. Thermalith is its first consumer.

This version changes how the library prints, so it is a minor bump.

## Changed

- **Print task per model now follows [niimbluelib](https://github.com/MultiMote/niimbluelib).** `KnownPrinterFacts.ResolvePrintTask` takes niimbluelib's model-to-task table (`modelPrintTasks` / `findPrintTask`), keyed by model id. Resolution order: hardware-verified models pinned to the task they were verified on (B1, B4, B3S_P on B1; D11_H on D110M-v4); a model + protocol-version entry; a model entry; then, for unlisted models, protocol 4 or higher gets D110M-v4. niimbluelib tasks we don't implement map to the nearest one we do (D11_V1 runs on the D110 path; B21_V1, B21_L2B and H1S stay on B1).
  - Moves: K3 (protocol 5) and B21 Pro, C1, EP1C to D110M-v4; B21S-C2B to D110; D101 and D110_M to B1 (D110_M on protocol 4 to D110M-v4). M2-H stays on B1.
- **The B1 Pro (4097) uses the D110M-v4 task, and D110M-v4 jobs finish once the requested page count is printed** with print progress at 100, without waiting for feed progress. The B1 Pro stops feed progress short of 100, so the job never ended (Thermalith #21).
- **RFID tag errors no longer fail a print.** `WriteRfidFail` (0x14), `RfidTagNotWritten` (0x1D) and `NotSupportWrittenRfid` (0x22) are logged through `NiimbotTrace` and the job carries on. They come from third-party, refilled or used-up rolls. If the printer stops after one (the expected reply never arrives, or print progress freezes for 15 s), `PrintAsync` throws a `PrintException` carrying that code. Every other error code still fails the print.

## Added

- **`PrinterErrorCode` covers niimbluelib's full list** (0x01-0x22, 0x32-0x35); it previously stopped at 0x10 plus 0x17.
- **`PrinterErrorCodeText`**: `Describe(code)` gives a short plain-language description, `Format(code)` gives "error code 0x14 (...)", and `IsNonFatal(code)` identifies the RFID tag codes above. `PrintException` messages use it.
- **`PrinterProfiles.FromModelId(int modelId, int? protocolVersion = null)`**: the optional protocol version feeds the print-task choice. `NiimbotClient` passes the version it reads on connect.

## Notes

- The print sequences themselves are unchanged; what changes is which models get which sequence.
- Removed: `KnownPrinterFacts.D110PrintTaskModelIds`, `D110MV4PrintTaskModelIds`, `UsesD110PrintTask` and `UsesD110MV4PrintTask`, replaced by `ResolvePrintTask`.
